# 面试问答：以当前实现为准

## 为什么不用五个固定 Agent？

原流程中知识节点先生成回答，汇总节点又重新生成且没有使用该答案，形成冗余调用。当前流程是 prepare→assistant→tools→assistant，工具结果以标准 tool 消息进入模型上下文。一次回答可以不调用工具，也可以在预算内继续查询；不能声称是自主规划或复杂多Agent协商。

## 怎么避免超卖？

应用使用 MySQL/InnoDB，先在事务中锁定当前客户行读取购物车，执行 `UPDATE products SET stock=stock-? WHERE stock>=? AND active=1` 并检查 rowcount。任意商品不足则整个事务回滚，订单、库存与购物车保持一致。并发测试让两个买家争抢最后一件商品，只有一笔成功。这证明的是本地数据库事务约束，不代表分布式高并发能力。

## 幂等在哪里？

下单的 `(user_id,request_key)` 有唯一约束。重试返回原订单；同一 key 使用不同地址会被拒绝。取消已取消订单直接返回，避免重复释放库存。AI确认先锁会话再锁操作记录，重新读取操作状态，并在同一事务中执行与更新为confirmed，重复确认返回已保存结果。

## 模型为什么不能越权？

工具 schema 禁止额外字段，不接受模型传 user_id。身份从登录会话取得并由服务端绑定工具执行；订单查询与变更必须同时满足 order_id 和 user_id。即使提示词被注入，代码层仍会拒绝其他用户订单。提示词只是辅助，权限不由模型决定。

## 为什么AI写操作需要确认？

模型输出可能不符合用户意图，数据也会在提议和执行间变化。先保存有用户范围、有期限的待确认记录；用户点击后再校验权限、订单状态和库存，最后事务执行。模型无法调用confirm API，也没有支付、发货、退款工具。

## SSE是真的流吗？

模型通过 httpx.AsyncClient 原生流读取 `data:`，内容 delta 到达后即发给浏览器；工具调用参数按index拼接，完成后解析schema并执行。节点事件也在节点执行时发送，前端使用fetch的ReadableStream解析。规则模式只发送一次规则结果，不模拟Token产生。

## 多轮和checkpoint有什么区别？

会话与最终用户/助手消息保存在数据库，下一轮取最近16条作为上下文。当前不是LangGraph checkpoint；不会在进程崩溃后恢复到未完成节点。模型中间tool消息仅在当次工具循环中使用。

## 为什么用 MySQL，SQLite 又在哪里？

MySQL/InnoDB 是应用主库，使用 SQLAlchemy Core 与 PyMySQL、READ COMMITTED 事务和 SELECT FOR UPDATE 行锁。同一客户的购物车变更先锁客户，订单状态变更锁订单，确认操作先锁会话再锁提议；不是只换连接字符串。SQLite 用于快速隔离单测以及旧数据迁移来源。已经在本机 MySQL 8.0.28 跑过同一套业务回归；不能由此声称分布式库存或生产高并发。

## RAG改善了多少？

不能说整体效果提升。29条人工样例中的旧Jaccard与多粒度BM25对比，只能说明此语料上的检索结果。Top-3命中率相同，BM25在两个无词项匹配样例上返回空，Top-1仍低于旧算法。尚未做独立测试集、向量召回、语义改写或回答忠实度评测。

## 如何观察成本？

ai_runs保存耗时、成功模型调用、工具调用和供应商流返回的prompt/completion tokens。供应商未返回用量时为0，不代表免费；目前没有货币成本计算，也未记录重试请求的完整计费信息。真实金额需结合该模型当前价格及供应商账单。

## 现在还有什么不足？

真实支付/物流/退款未接入；没有订单超时自动回收、登录限流、生产监控和跨实例任务恢复。知识库很小，词项检索不解决所有语义改写。Playwright 已验证跨角色人工协作、密码提示、手机视口与退出登录后的客户上下文清理，但还没有生产用户验证。

## 人工接管如何避免与 AI 同时处理？

转人工关联当前会话和工单，系统提取最近对话、已查资料和工具结果形成交接摘要。接管期间 AI 请求由服务端返回409；客户可以补充问题，人工回复写入同一对话和工单事件。未确认的模型写操作被拒绝。结单后解除接管状态，后续 AI 查询读取已保存的处理结果。客服相关写操作统一按会话、工单的顺序加锁。

## 观测中的完成率能否代表回答准确率？

不能。执行完成仅指流程没有报错，规则模式也单独统计。首次响应是首次回答文本到达的耗时，工具耗时和 Token 用量是实际记录；模型答案和任务完成质量仍需独立标注评测。新增8项服务流程契约回归是规则模式，不是LLM效果评测。
