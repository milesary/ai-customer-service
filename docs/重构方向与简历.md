目标岗位：Python 后端 / AI 应用开发。当前定位：可演示业务闭环的个人学习项目，不是生产电商。

## 本次实现与证据

| 原问题 | 当前实现 | 可验证材料 |

| 模型写操作直接执行的风险 | 提议→用户确认→重新校验→事务执行；确认记录幂等 | 过期、重放、状态变化与权限测试 |

| 缺少结果记录 | 运行耗时、成功模型调用数、工具调用数、供应商 Token 用量 | ai_runs 表与管理页面 |

## 现在可用的简历段落

使用前请确认你实际理解、运行并能解释这些实现；AI 辅助编写代码不能直接等同于你已掌握。

**购物 SHOPPING · AI 电商客服｜个人项目｜Python / FastAPI / Next.js / LangGraph / MySQL / SQLAlchemy**

- 实现商品选购、购物车、订单及售后闭环，通过数据库事务与条件库存更新防止超卖，使用请求幂等及状态校验处理重复下单、取消和模拟支付。
- 基于 LangGraph 构建有界工具调用循环，将商品搜索、用户订单和政策检索接入 AI 助手；实现持久多轮会话及模型原生 SSE 输出，展示资料来源和业务处理记录。
- 为 AI 写操作设计“提议—确认—执行”流程，将用户权限范围绑定到服务端身份，确认时再次检查库存与订单状态，避免越权与重复执行。
- 建立业务回归测试、检索对比脚本及运行记录，覆盖库存竞争、事务回滚、工具参数校验、操作重放和售后处理场景。

可按篇幅选3条。测试数与实测结果以 `验证记录.md` 为准。
不要写“生产上线”“高并发”“降低幻觉百分比”“分布式事务”“自研大模型”“支持真实退款”，目前没有这些证据。
检索尚未证明 Top-1 或回答准确率提升，不应将 BM25 更换本身包装成效果提升。

## 按目标岗位继续深化

### Python 后端

1. 加入待支付订单过期与库存释放任务，测试任务重试和重复执行。
2. 在现有 MySQL 主库上完善显式 schema 版本迁移、备份恢复及多实例事务验证；当前版本已提供旧 SQLite 只读迁移与连接池。
3. 做固定硬件与固定请求分布的压测，分别报告非AI接口吞吐与AI响应耗时；记录错误率及 p50/p95。
4. 完善登录限流、部署配置、审计与备份恢复，再讨论外部部署。

### AI 应用

1. 扩充真实但已脱敏的商品说明和政策语料，分开调参集与保留测试集。
2. 在相同语料、标注和预算下比较关键词、多粒度 BM25、向量召回及混合召回。
3. 记录“工具名正确率、参数正确率、任务完成率、引用一致性、无答案拒答率”，不要只看回答是否流畅。
4. 加入注入文本、模糊指代、参数缺失、工具失败和多商品比较样例；权限始终由代码保证。

## 面试风险与最快补证据

最高风险：项目是 AI 辅助完成，但无法解释为什么事务能防止超卖、为什么确认不能由模型替代、真实 SSE 和回放有什么区别。

建议先独立完成一次：买家下单→模拟支付→管理员发货→买家收货→AI提议售后→用户确认→管理员处理。
随后读懂一个库存竞争测试和一个模型工具协议测试，自己新增一个失败场景并解释结果。
保留运行录像、测试日志、评测 JSON 和你自己的改动记录，比增加更多技术栈更有用。
